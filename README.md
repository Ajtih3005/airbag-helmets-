# Smart Airbag Helmet — Pre-Impact Rider State Classifier

> An untethered, self-contained smart helmet module that continuously captures IMU data at 1000 Hz,
> classifies the rider state using ML, and deploys an airbag in under 20 ms of a crash event.

---

## Classification Labels (3-class per spec)

| Label | ID | Description |
|---|---|---|
| Normal | 0 | Stable riding, gravity-dominant, low noise |
| Near-Crash | 1 | Pothole / sudden brake / near-miss (warning only) |
| Crash | 2 | Multi-axis impact spike, gravity loss, airbag deploys |

## ML Pipeline

```
Synthetic IMU Data (300 sessions x 2000ms @ 1000Hz)
    MPU6050: ax, ay, az, gx, gy, gz
    ADXL377: hg_ax, hg_ay, hg_az (up to 200g high-impact)
         |
         v
Sliding Window (200 samples = 200ms, stride=100ms)
         |
         v
Feature Extraction (81 features per window)
    Per-axis stats: mean, std, max, min, range, rms, iqr, skew
    Magnitudes: accel_mag, gyro_mag, hg_mag
    Derived: SMA, jerk, tilt angle, cross-axis correlations, hg_peak_ratio
         |
         v
Model Training (RF, XGBoost, SVM, KNN, DT)
    Best: Random Forest   Accuracy=98.16%  F1=0.9613
         |
         v
Live Prediction Loop
    Multi-check gate: 3 consecutive Crash windows required before deploy
    Near-Crash: LED/buzzer warning (GPIO 27)
    Crash: Airbag trigger (GPIO 17) + SMS via SIM800L
    Persistent lock file: one-time deploy only
```

## Quickstart

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Generate synthetic dataset
```bash
python src/data_generator.py
```

### 3. Train model
```bash
python src/train_model.py
```

### 4. Run live simulation
```bash
# Synthetic scenario (Normal -> Near-Crash -> Crash -> Normal)
python src/predict.py --reset-lock

# Replay a specific session from the dataset
python src/predict.py --session 5
```

### 5. Run live dashboard
```bash
python app/dashboard.py --reset-lock
```

### 6. Raspberry Pi deployment (live ESP32 data)
```bash
# Simulate without hardware
python src/raspberry_pi_interface.py --simulate

# Real ESP32 over UART + GPIO output
python src/raspberry_pi_interface.py --port /dev/ttyUSB0 --hardware
```

### 7. Export model for ESP32 (C++ firmware)
```bash
pip install m2cgen skl2onnx onnxruntime
python src/deploy_model.py --target both
# Outputs: models/export/model_predictor.h  (copy to Arduino sketch)
# Outputs: models/export/model.onnx         (use on Raspberry Pi with onnxruntime)
```

## Safety Architecture

```
Sensor Sample (1 ms @ 1000 Hz)
      |
      v
Rolling Buffer (200 samples)
      |
      v  (every 100 ms = STRIDE)
Feature Extraction + ML Inference (0.13 ms)
      |
      +--[Near-Crash]---> Warning: GPIO pulse LED/buzzer
      |
      +--[Crash prob > 0.70]---> consecutive_crash_counter++
                                      |
                              (if counter >= 3)
                                      |
                                      v
                           AIRBAG DEPLOY (GPIO 17 HIGH)
                           + SMS via SIM800L UART
                           + Write persistent lock file (AIRBAG_DEPLOYED.lock)
                           + Log to logs/prediction_log.csv
```

## Hardware Wiring (Raspberry Pi)

| Signal | GPIO (BCM) | Connected to |
|---|---|---|
| Airbag trigger | GPIO 17 | MOSFET gate -> solenoid valve |
| Warning LED/Buzzer | GPIO 27 | LED / buzzer circuit |
| ESP32 UART TX | /dev/ttyUSB0 | UART RX on Raspberry Pi |
| SIM800L UART | /dev/ttyAMA0 | SIM800L TX |

### ESP32 Serial Protocol
The ESP32 must stream sensor readings over UART at 115200 baud, one line per sample:
```
ax,ay,az,gx,gy,gz,hg_ax,hg_ay,hg_az\n
0.12,-0.05,9.83,1.2,-0.8,0.3,0.12,-0.05,9.83
```
